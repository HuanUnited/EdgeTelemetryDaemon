# Edge Telemetry Daemon (ETD)

Edge Telemetry Daemon (ETD) — это высокопроизводительный, экономичный по ресурсам сборщик
телеметрии и замкнутый регулятор ресурсов на основе обнаружения аномалий, написанный на Go для
периферийных Linux-устройств и систем инференса ИИ. Демон собирает статистику учёта ядра хоста
и метрики инференс-конвейера, выполняет потоковую статистическую фильтрацию по двум временным
горизонтам без выделения памяти в куче на горячих путях, динамически регулирует собственную
квоту CPU через cgroup v2 между состояниями покоя и всплеска в ответ на обнаруженные события, и
отправляет структурированные оповещения об аномалиях и дрейфе на центральные бэкенды телеметрии
по HTTP.

## Цель проекта: замкнутое регулирование CPU

Изначальная архитектура ETD работала с фиксированным интервалом опроса, детектором на основе
одного горизонта EWMA/Welford и без собственного управления ресурсами. С тех пор демон был
полностью доработан под единую цель: **автономное замкнутое регулирование квоты CPU через
cgroup v2, потоковое отслеживание концептуального дрейфа по двум горизонтам и адаптивная частота
опроса** — чтобы агент мог находиться на квоте в 5% CPU в состоянии покоя, распознавать как
резкие аномалии, так и медленный дрейф собственных входных данных, переходить на полную квоту
CPU для быстрой реакции и возвращаться в состояние покоя после нормализации условий — без
участия человека или внешнего контроллера. Все пять запланированных фаз реализованы и слиты в
основную ветку:

| Фаза | Область | Статус |
| :--- | :--- | :--- |
| 1 | Базовое укрепление и переносимость (заглушка сборки для не-Linux, исправление порчи gauge-метрик, исправление пробуждения потребителей outbox) | ✅ Готово |
| 2 | Движок дрейфа по двум горизонтам (быстрый/медленный EWMA, `Δ_drift`, защита от насыщения) | ✅ Готово |
| 3 | Контроллер квот `internal/cgroup` v2 | ✅ Готово |
| 4 | Замкнутая оркестрация агента (адаптивная выборка `τ(Z)`, переключение квоты по состоянию) | ✅ Готово |
| 5 | Верификация и бенчмарки (набор регрессионных тестов на нулевые аллокации, стресс-тест CFS, тест взаимных помех нескольких арендаторов) | ✅ Готово |

Полный набор тестов (`go test -race -count=1 ./...`) проходит успешно во всех пакетах
(`cmd/agent`, `internal/cgroup`, `internal/collector`, `internal/config`, `internal/engine`,
`internal/filter`, `internal/metrics`, `internal/outbox`, `internal/transport`), а инварианты
нулевых аллокаций на горячих путях соблюдаются от начала до конца — см. раздел
[Бенчмарки производительности](#бенчмарки-производительности).

## Архитектура

Конвейер телеметрии обрабатывает данные последовательными этапами, спроектированными для
детерминированной задержки и ограниченного потребления памяти, с обратной связью от обнаружения
как к частоте опроса, так и к собственной квоте CPU демона:

```
[ Linux /proc и AI-коллектор ]
              │
              ▼
[ Потоковый движок с двумя горизонтами ] ── (Дрейф EWMA fast/slow + дисперсия Welford + защита от насыщения)
              │
              ▼
[ Подавитель "мёртвой зоны" и кольцевой буфер ] ── (Гистерезисный фильтр + окно до срабатывания)
              │              │
              │              └──────────────► [ Контроллер квот cgroup v2 ]
              │                                  Покой (5%) ⇄ Всплеск (100%)
              ▼
[ Ограниченная очередь Outbox ] ── (пробуждение через sync.Cond broadcast, DropOldest/DropNewest)
              │
              ▼
[ Отказоустойчивый HTTP-диспетчер ] ── (Экспоненциальный backoff + джиттер)

     Z-оценка / индекс дрейфа также питают τ(Z) ──► контроллер динамического интервала опроса
                                                     (τ_min при аномалии ⇄ τ_max в покое)
```

### Подсистемы

* **internal/collector**: сборщики метрик без выделения памяти, парсящие `/proc/stat` и
  `/proc/meminfo` через прямые сырые системные вызовы (`SYS_OPENAT`, `SYS_READ`, `SYS_CLOSE`) и
  буферы на стеке, а также конкурентный синтетический генератор инференса ИИ (`AIGen`).
  Платформо-независимые типы теперь вынесены в `types.go`; сборка для не-Linux платформ теперь
  проходит успешно и возвращает типизированную ошибку `ErrUnsupportedPlatform` вместо провала
  компиляции.
* **internal/engine**: онлайн-статистический движок, реализующий алгоритм Уэлфорда для расчёта
  среднего и дисперсии за $O(1)$, **EWMA по двум горизонтам** (независимые быстрый и медленный
  коэффициенты сглаживания) для отслеживания концептуального дрейфа, нормализованный индекс
  расхождения дрейфа (`Δ_drift = |EWMA_fast − EWMA_slow| / max(1.0, EWMA_slow)`), и абсолютную
  защиту от насыщения памяти (`IsSaturated`), которая принудительно фиксирует аномалию вне
  зависимости от Z-оценки, если доступная память опускается ниже заданного процента.
* **internal/cgroup**: нативный контроллер Linux cgroup v2, управляющий `cpu.max` и `cpu.stat`
  в пределах настраиваемого корня cgroup. `SetBurst()`/`SetQuiescent()` идемпотентны (ноль
  операций записи в файловую систему при повторном вызове в том же режиме); `ReadCPUStat()`
  парсит учёт троттлинга CFS (`nr_periods`, `nr_throttled`, `throttled_usec`) без выделения
  памяти в куче.
* **internal/filter**: конечный автомат подавителя "мёртвой зоны" (`StateNormal` /
  `StateAlerting` / `StateSuppressed`), предотвращающий шторм оповещений — его переходы
  состояний теперь напрямую управляют `cgroup.Controller.SetBurst`/`SetQuiescent` — кольцевой
  буфер фиксированной ёмкости, хранящий контекст до срабатывания для аномальных интервалов, и
  периодический агрегатор heartbeat.
* **internal/outbox**: потокобезопасная ограниченная очередь с выбираемыми стратегиями
  переполнения (`DropOldest` против `DropNewest`), отменой по контексту и немедленной сборкой
  мусора вытесненных элементов. Пробуждение потребителей теперь управляется через
  `sync.Cond.Broadcast()` при каждом изменении состояния, а не через канал уведомлений с одним
  слотом, поэтому несколько одновременных вызовов `Pop()` больше не могут пропустить пробуждение.
* **internal/transport**: HTTP/JSON-диспетчер телеметрии с циклами повторных попыток, случайным
  джиттером, экспоненциальным backoff и надёжной доставкой полезной нагрузки.
* **internal/metrics**: реестр метрик в текстовом формате Prometheus без внешних зависимостей,
  предоставляющий счётчики и gauge-метрики среды выполнения на `/metrics`. `Set`/`Add` для
  gauge-метрик теперь корректно разделяют хранение битов float и накопление счётчика (пути кода
  больше не пересекаются).
* **internal/config**: конфигурация среды выполнения на основе переменных окружения со строгой
  валидацией инвариантов, теперь включающая параметры адаптивной частоты и cgroup ниже.
* **cmd/agent**: цикл оркестрации. `computeInterval(z, τ_min, τ_max, θ)` реализует
  `τ(Z_t) = τ_max − (τ_max − τ_min) · min(1.0, |Z_t|/θ)` и перезапускает тикер опроса на каждом
  цикле; переходы состояний подавителя вызывают контроллер cgroup; новое пересечение индекса
  дрейфа отправляет `EventDriftAlert` в outbox параллельно с уже существующим путём оповещения
  об аномалиях.

## Конфигурация

ETD настраивается через переменные окружения:

| Переменная | Тип | По умолчанию | Описание |
| :--- | :--- | :--- | :--- |
| `ETD_LISTEN_ADDR` | строка | `:8080` | Адрес host:port для привязки эндпоинтов Prometheus `/metrics` и проверки состояния |
| `ETD_SCRAPE_INTERVAL` | duration | `5s` | *Начальная* частота опроса коллекторов хоста; адаптивно сжимается/расширяется во время работы между `ETD_RATE_TAU_MIN` и `ETD_RATE_TAU_MAX` |
| `ETD_DETECTOR_MIN_SAMPLES` | int | `30` | Минимальное число выборок Уэлфорда до активации оценки Z-score и дрейфа |
| `ETD_CPU_REPORT_MODE` | строка | `percent` | Единица измерения CPU (`percent`, `ticks` или `hertz`) |
| `ETD_LOG_LEVEL` | строка | `info` | Уровень детализации структурированного логирования (`debug`, `info`, `warn`, `error`) |
| `ETD_PROCFS_PATH` | строка | `/proc` | Базовый путь монтирования procfs для сбора метрик хоста (например, `/host/proc` в контейнерах) |
| `ETD_TARGET_URL` | строка | `http://localhost:8080/ingest/dummy` | Удалённый эндпоинт приёма для отправляемых оповещений и heartbeat |
| `ETD_RATE_TAU_MIN` | duration | `50ms` | Нижняя граница интервала опроса при пиковой аномалии (максимально быстрая реакция) |
| `ETD_RATE_TAU_MAX` | duration | `5s` | Верхняя граница интервала опроса в состоянии покоя (минимальные накладные расходы) |
| `ETD_RATE_THETA` | float | `3.5` | Масштаб чувствительности Z-score для контроллера интервала `τ(Z)` |
| `ETD_CGROUP_ROOT` | строка | `/sys/fs/cgroup` | Корневой путь файловой системы иерархии cgroup v2, которой управляет данный демон |

## Быстрый старт с Docker Compose

Разверните демон вместе с фиктивным приёмником данных:

```bash
# Запуск демона и фиктивного приёмника
docker compose up -d --build

# Проверка состояния контейнеров
docker compose ps

# Считать метрики Prometheus
curl -s http://localhost:8080/metrics

# Спровоцировать синтетический всплеск аномалии и понаблюдать за реакцией замкнутого контура
curl -s -X POST http://localhost:8080/inject/anomaly
```

### Конфигурация Docker Compose

```yaml
services:
  agent:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: edge-telemetry-daemon
    ports:
      - "8080:8080"
    volumes:
      - /proc:/host/proc:ro
      - /sys/fs/cgroup:/sys/fs/cgroup:rw
    environment:
      - ETD_LISTEN_ADDR=:8080
      - ETD_SCRAPE_INTERVAL=100ms
      - ETD_DETECTOR_MIN_SAMPLES=30
      - ETD_CPU_REPORT_MODE=percent
      - ETD_LOG_LEVEL=debug
      - ETD_PROCFS_PATH=/host/proc
      - ETD_TARGET_URL=http://ingest-sink:80/post
      - ETD_RATE_TAU_MIN=50ms
      - ETD_RATE_TAU_MAX=5s
      - ETD_RATE_THETA=3.5
      - ETD_CGROUP_ROOT=/sys/fs/cgroup
    depends_on:
      - ingest-sink
    restart: unless-stopped

  ingest-sink:
    image: kennethreitz/httpbin
    container_name: telemetry-ingest-sink
    ports:
      - "8081:80"
    restart: unless-stopped
```

> **Примечание**: запись в `cpu.max` требует, чтобы контейнер имел доступ к реальному листовому
> узлу cgroup v2 (и делегированный контроль над ним) — в большинстве container runtime это
> означает монтирование cgroup в режиме чтения-записи, как показано выше, и указание на
> делегированное поддерево, а не на корень хоста в мультиарендных окружениях.

`go test -race -count=1 ./...`, включая новый интеграционный тест
`TestEndToEndQuotaRegulation`, который прогоняет полный цикл
инъекция → обнаружение → подавление → всплеск квоты → остывание → покой квоты и во время
прогона корректно зафиксировал как оповещения о дрейфе (`drift_index` в диапазоне 0.16–3.4), так
и оповещения об аномалиях (`z_score` от ~6 до ~12 при заданных всплесках пропускной способности).

> **Ещё не обновлено**: показатели нагрузочного теста и усреднения `benchstat` из
> дореформенного базового состояния здесь намеренно не приводятся, а не оставлены устаревшими,
> поскольку они относятся к периоду до появления контроллера квот cgroup и больше не отражают
> установившееся поведение (демон теперь проводит большую часть времени на квоте 5%, а не без
> ограничений). Перед публикацией новых цифр нагрузочного теста перезапустите
> `hey -z 10m -c 50` и `benchstat` на текущей сборке.

## Набор тестов

### Модульные тесты и обнаружение гонок

Запуск модульных тестов по всем пакетам с включённым детектором гонок:

```bash
go test -v -race -count=1 ./...
```

### Бенчмарки на нулевые аллокации

Проверка производительности и отсутствия аллокаций в куче на горячих путях:

```bash
go test -bench=. -benchmem ./...
```

### Регрессия нулевых аллокаций (явные проверки)

Каждый пакет с горячим путём содержит `zero_alloc_test.go`, напрямую проверяющий
`testing.AllocsPerRun(...) == 0`, поэтому будущее изменение, случайно вносящее аллокацию,
провалит `go test`, а не просто останется незамеченным в бенчмарке:

```bash
go test -run TestZeroAlloc ./...
```

### Стресс-тест троттлинга CFS

Проверяет `internal/cgroup.Controller.ReadCPUStat` под конкурентным чтением на фоне непрерывно
изменяемого файла `cpu.stat`:

```bash
go test -race -run TestCgroupStress ./internal/cgroup
```

### Тест взаимных помех нескольких арендаторов

Запускает два независимых экземпляра `Agent` на двух разных корнях cgroup одновременно и
проверяет, что состояние оповещений/квоты одного не просачивается в другой:

```bash
go test -race -run TestInterference ./cmd/agent
```

### Фаззинг-тестирование с покрытием

Фаззинг-тестирование парсеров хоста, математических движков и конечных автоматов подавления:

```bash
# Фаззинг парсера CPU для Linux
go test -fuzz=FuzzParseCPULine -fuzztime=30s ./internal/collector

# Фаззинг парсера Meminfo для Linux
go test -fuzz=FuzzParseMemInfo -fuzztime=30s ./internal/collector

# Фаззинг онлайн-алгоритма дисперсии Уэлфорда
go test -fuzz=FuzzWelfordEquivalence -fuzztime=30s ./internal/engine

# Фаззинг переходов состояний подавителя "мёртвой зоны"
go test -fuzz=FuzzSuppressorProcess -fuzztime=30s ./internal/filter
```
